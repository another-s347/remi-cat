## 已实现

### 创建文件时准备父目录

[fs_write](/home/skye/remi-cat/crates/bot-core/src/tools/mod.rs:543) 在写文件前通过同一个 Sandbox 创建所需父目录，再执行写入。无需先发送完整文件、失败后另建目录、再发送相同内容。

本地路径与 Docker 工作区路径沿用现有 Sandbox 的解析规则。测试覆盖嵌套创建、覆盖已有文件、拒绝 `..` 和指向工作区外的符号链接；Docker 测试只使用宿主目录映射的文件工具，不启动容器。

### 文本读取在溢出前分页

[read_budget.rs](/home/skye/remi-cat/crates/bot-core/src/tools/read_budget.rs) 从 [当前 CatAgent](/home/skye/remi-cat/crates/bot-core/src/agent.rs:521) 获得有效工具输出预算，而非假设静态工具注册时的默认模型。预算只放在此次工具上下文 metadata，不写入用户状态。

默认读取和显式大范围读取都受预算约束；返回内容和封装一起计量，计入脱敏后的文本增长。输出带实际 `offset/length/remaining`，可以继续读。正常 UTF-8 分页保留字符边界；无效 UTF-8 转码膨胀也受预算约束。

按行读取能放入预算时保留原来的行格式；超大行范围明确退化为字节分页，提供继续读取的位置，不伪装已完整返回请求的行。图片路径继续输出多模态内容。极小到连分页元数据也放不下的预算仍交给原有溢出保护处理。

作用范围是内置 `fs_read`。ACP 或宿主自定义的文件工具没有被替换。读取仍沿用原有文件加载方式，本次不宣称降低磁盘读取或内存开销。

### Todo 批量完成与状态正确性

[todo__complete](/home/skye/remi-cat/crates/bot-core/src/todo/tools.rs) 兼容原来的 `{"id":1}`，新增 `{"ids":[1,2,3]}`。解析先验证参数；后端在一次用户状态锁内验证所有 ID，再一次提交完成状态。存在未知 ID 时整个批次不改动；完整完成后仍遵循已有批次清理和 ID 单调递增规则。

保持原有 `done` 存储格式和界面语义，没有引入另一套未接入界面的 `in_progress` 字段。[默认 agent 提示](/home/skye/remi-cat/.remi-cat/agents/default.md:58) 与实际工具一致：验证成功后再完成任务、已完成项可以批量提交，`todo__update` 只修改标题。补充合并独立读写、定位大文件先搜索和检查测试确实执行的指导。

新建 profile 会使用更新后的内置默认 agent。已有自定义 agent 提示不会被自动覆盖。

## 同条件真实对比

先构建包含当时已有修改的 baseline，复制为独立二进制，再实现优化并构建另一个二进制。两个二进制均冻结并记录 SHA-256。原先五个已修改文件被保留：四个文件内容完全相同，`agent.rs` 仅增加一行预算注入；保留核对记录位于证据目录。

模型和任务沿用前一轮：`kimi-k2.6`、temperature 0.6、thinking disabled、max output 8192、工具输出上限 24000 bytes；CSV、retry、日志任务各跑两次，两侧各六次。全新目录、profile 和会话；两个工作进程；统一独立验收 v2。两侧主请求工具名称和数量均保持相同。

| 指标 | 优化前 | 优化后 | 此组变化 |
|---|---:|---:|---:|
| 独立验收通过 | 6/6 | 6/6 | 保持 |
| 有 usage 的有效模型轮次 | 84 | 66 | **−21.4%** |
| 累计输入 tokens，含缓存 | 542,496 | 445,364 | **−17.9%** |
| 未缓存输入 tokens | 113,696 | 106,420 | **−6.4%** |
| 输出 tokens | 10,296 | 7,483 | **−27.3%** |
| 纯 Todo 轮次 | 21 | 12 | −42.9% |
| 缺父目录的写入失败 | 2 | 0 | 消失 |
| fs_read 超限丢弃 | 2 | 0 | 消失 |

所有 token 数来自 API usage；缓存是输入子集。上述降幅不是费用降幅。

服务端存在 overload/429：优化前 25 次，优化后 12 次，没有 usage。它们单列在 transport errors 中，不计为模型决策轮次，也不把减少的 429 重试归功于代码。有效请求均有 usage；所有任务正常退出并通过独立验收。不用两组耗时推断速度收益。

### 分任务结果：收益存在差异

每项为两次合计。

| 任务 | 轮次：前 → 后 | 输入：前 → 后 | 输入变化 |
|---|---:|---:|---:|
| CSV | 35 → 28 | 218,749 → 170,202 | −22.2% |
| retry | 36 → 28 | 232,339 → 164,884 | −29.0% |
| 日志 | 13 → 10 | 91,408 → 110,278 | **+20.6%** |

日志的轮次更少、输入却更多：优化后两次都先读取了实际日志内容，再搜索/读命中附近。原先一次先读超限后退回搜索，另一次走了较短的搜索路径；现在预算内的初始页面会作为真实内容进入后续历史。**消除超限恢复并不自动等于减少该任务 token。** 后续应单独验证“先搜索后定点读取”的策略，不能为追求这道日志题的成绩而直接缩小所有文件的默认读取能力。

优化后 retry 第一次：同轮发出实现写入和导出补丁，最后以 `ids:[1,2,3,4]` 一次完成；有效轮次 16 → 12。CSV 第一次 22 → 15，包含批量写测试文件和批量完成 Todo。模型仍有主动 mkdir、无关目录探索和部分重复测试，尚未全部消除；批量接口只是提供能力，不能保证每次调用策略最优。

## 验证和边界

- 文件读取/写入相关测试 15 项通过，其中包括 ACP 已有范围解析回归。
- Todo 测试 20 项通过，含新旧参数、混合未知 ID 不部分提交、批次清理、ID 单调与并行完成不覆盖状态。
- 分页纯函数测试 2 项通过，含多页 UTF-8 重建、无效 UTF-8、脱敏膨胀、单字节请求的推进。
- 新增符号链接场景后，额外重跑父目录写入测试通过。共 37 个不同的针对性测试，部分测试重复运行。
- `cargo build --offline -p remi-cat` 成功；所改 Rust 文件通过 scoped rustfmt，`git diff --check` 通过。全仓 `cargo fmt --all --check` 存在本次改动之外的既有格式差异，没有一并格式化无关文件。
- 两侧共 12 次真实任务均通过独立验收。单模型、小任务、每类两次，结果不是长期稳定收益的统计证明。多个机制一起改变，不能将总体降幅全部归因于某一项。
- 本次验证是 Linux 源码/调试构建和真实 API 回归，未制作 Windows 安装包、升级正在使用的实例或发布版本。
