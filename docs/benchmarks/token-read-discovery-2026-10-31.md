# 大文件首次预览：第二轮 token 优化

2026-10-31。承接[上一轮工具/轮次优化](token-round-optimization-2026-10-31.md)，这轮只改内置 `fs_read` 的大文件默认读取行为及其说明、测试。默认 profile、Todo 和写文件实现保持上一轮版本，工具集合仍为 26 个。

## 为什么改

上一轮解决了“读取 32 KiB 后超过 24000 bytes 输出预算”的失败恢复，但无范围读取会立即返回预算允许的约 23 KiB。定位一个已知标识符时，这段大文件头往往没有所需信息，却会跟随后续模型请求重放。

已保存轨迹中，日志第一次的工具返回历史约有 7,700 个 cl100k 估算 tokens；后面几轮继续携带。这个问题应通过逐步获取所需内容处理，而非让模型丢掉必要验证、裁掉默认工具或默默截断全文。

## 新行为

- **文件超过 32 KiB，且未指定字节/行范围**：先返回至多 4 KiB 预览，标明文件总大小、实际返回长度、剩余字节和下一位置，提示用 `rg` 定位或显式请求范围。
- **显式 `offset`、`length` 或行范围**：继续走上一轮预算内分页路径，保留大范围读取能力。
- **32 KiB 以内文件**：沿用上一轮读取规则，仍受当前输出预算约束。
- 图片继续优先走多模态返回。预览阈值按文件字节大小判断，不检查文件名、任务类型或某个 benchmark 标识符。

实现：[read_budget.rs](/home/skye/remi-cat/crates/bot-core/src/tools/read_budget.rs)、[fs_read](/home/skye/remi-cat/crates/bot-core/src/tools/mod.rs)。此次没有增加工具，也没有继续修改默认 agent 提示。

## 同条件真实回归

基线使用上一轮冻结的优化后二进制；新实现另行构建并冻结。Kimi `kimi-k2.6`、temperature 0.6、thinking disabled、max output 8192、输出预算 24000 bytes、两个工作进程，仍为 CSV / retry / 日志各两次，两侧各 6 次。每次使用独立新 profile、目录和会话；独立验收 v2。

两组 **均 6/6 通过**。本轮 149 次请求全部有 HTTP 200 和 usage，没有服务端重试或缺失 usage。

当前可确认的是：首次无范围读取的大文件内容显著减少，目标检索任务两次都正确完成；整体未缓存输入几乎持平，没有证明普遍费用收益。下一处值得分析的是编码任务的探索和修复循环。

## 兼容性、取舍和验证

- 首次预览不会代表文件已完整读取。验证新增了 66,023 bytes 文本：从预览开始，按返回位置继续读取，最终逐字节重建原文件，包括末尾标记和换行。
- 显式请求 32768 字节仍可读取原范围；有当前模型预算时按该预算分页。末尾指定行读取、UTF-8、普通文本、小文件、图片和已有读写回归均通过，文件相关测试 **16 项通过**。
- 大文件全文任务若先无范围预览再继续，可能多一次初始读取。已知需要全文时可直接指定范围。本轮没有用长文总结任务证明其质量或轮次收益。
- 当前实现仍先加载文件，再限制模型看到的文本；此轮不宣称减少磁盘 I/O 或进程内存。
- 构建 `cargo build --offline -p remi-cat` 成功；所改文件 scoped rustfmt、脚本编译和 `git diff --check` 通过。
- 对比工具名称/数量一致，保留源文件哈希、冻结二进制哈希、逐轮请求/响应、验收和第一阶段保留核对。没有改动原有无关工作区修改。
- 当前为源码与 Linux 调试构建验证，尚未发布或升级已安装实例。缓存为输入子集；token 降幅不直接等同费用降幅。
